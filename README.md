# Research support backend

FastAPI API for the Research developer portal and the `self-evolving-workflow` Python library. Uses PostgreSQL with pgvector and SQLAlchemy. Local editable dependency points to the adjacent `Reserch-Developer-Package` clone.

## Setup

```powershell
uv sync --group dev
# Only if .env does not exist:
Copy-Item .env.example .env
# Configure DATABASE_URL in .env before starting.
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Use a PostgreSQL database with pgvector available. Startup creates missing tables and enables the vector extension; it does not alter existing columns or delete records. The new `user_sessions` table is additive. An explicit migration system should replace startup schema creation before production deployment.

Open http://127.0.0.1:8000/docs for the live API contract. The checked-in `openapi.json` is a legacy snapshot; use the live schema at `/api/v1/openapi.json`.

## Portal API

All routes use the `/api/v1` prefix:

| Method | Path | Behavior |
| --- | --- | --- |
| POST | `/auth/register` | Create an account and session; password minimum 12 characters |
| POST | `/auth/login` | Create/rotate a browser session |
| GET | `/auth/me` | Return current user |
| POST | `/auth/logout` | Delete session and cookie |
| GET, POST | `/projects` | List owned projects / create project |
| GET | `/projects/{project_id}` | View owned project |
| GET, POST | `/projects/{project_id}/api-keys` | View / generate project keys |
| DELETE | `/projects/{project_id}/api-keys/{key_id}` | Revoke project key |

Browser authentication uses an opaque random token in an HttpOnly SameSite=Lax cookie. Database sessions store only the token digest, expire after `SESSION_HOURS`, and are invalidated on logout. Passwords use independently salted scrypt hashes. Email addresses are normalized to lowercase. Every project and key route checks the current user's ownership; other users receive 404.

Cookie-authenticated POST/DELETE requests must send an `Origin` matching `ALLOWED_ORIGINS`. For direct REST clients, explicitly supply an allowed development origin. Existing SDK tool routes use `X-API-Key` and do not use browser sessions. Keys generated by the portal work with `Research.configure(projectApiKey=...)`; revocation makes future SDK requests fail immediately.

No real credentials belong in source control. `.env` is ignored. For HTTPS production, use `SESSION_COOKIE_SECURE=true` and set `ALLOWED_ORIGINS` to the exact frontend origin. Deploy frontend and `/api` on the same origin.

## Research demo routes

The existing `/client-test/*` demo routes initialize AI workflows during import and may make paid model calls. They are disabled by default. Set `ENABLE_CLIENT_TEST_ROUTES=true` only in a configured local research environment to restore them. Portal and AI tool database routes work without OpenRouter credentials.

## Tests

```powershell
uv run pytest -q
```

Tests use an isolated in-memory SQLite database through a FastAPI dependency override. They cover session rotation, hashing, expiry/logout, validation, origin checks, project/key isolation, SDK authentication and key revocation. They do not connect to `.env`'s database or exercise vector similarity/external AI requests.

An optional live check is available with `.venv/Scripts/python.exe -m scripts.smoke_portal` after both local servers are running. It exercises the production routes against the configured PostgreSQL database inside a transaction and rolls back all test records, then checks the frontend route and API proxy. It makes no model calls and prints no secrets. This check passed against the supplied Neon configuration.
